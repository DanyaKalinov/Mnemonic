# Глубина UI-контроля: Ева управляет интерфейсом как человек

Дата: 2026-09-15
Статус: черновик дизайна (одобрен по секциям владельцем)

## 1. Контекст и цель

Агент Евы (десктоп, `eva_agent/`) уже умеет ~31 действие: открывать
приложения/файлы/сайты, работать с файлами, кликать мышью и клавиши,
управлять win32-контролами по имени, «смотреть» на экран через локальную
модель (Qwen2.5-VL, Ollama), следить по watch-правилам.

Цель этой работы — **глубина UI-контроля**: агент должен выполнять
практические задачи в приложениях так, как их делает человек, по команде
на обычном языке («напиши Диме в телеграм: встретимся в 12»), сам находя
нужные элементы интерфейса.

Выборы владельца (брейншторм, 2026-09-15):
- Приоритет: **глубина UI-контроля**.
- Режим управления: **целевой** — Ева сама планирует достижение цели.
- Мишень первого релиза: **нативные Windows-приложения через UI Automation
  (UIA), фолбэк — VLM по скриншоту (координаты кнопок)**.
- Кейс-успех: **отправить сообщение в здешний мессенджер (Telegram Desktop)**.
- Политика подтверждений: **мягче** — отправка сообщений БЕЗ подтверждения;
  confirm остаётся только для удаления/перезаписи файлов (как сейчас).

## 2. Архитектура

Новые компоненты живут в `eva_agent/` (не в git-репозитории сервера):

### 2.1 `ui_automation.py` — UIA-адаптер (новый)
Библиотека: `uiautomation` (Windows UI Automation). Публичные функции —
строгие запросы, БЕЗ LLM (быстро, предсказуемо):
- `get_window_elements(window)` — дерево активного окна: роли, тексты,
  координаты, состояния (роль UIA: button, edit, list, menu item…).
- `click_by_text(window, text)` — клик по элементу с заданным текстом
  (кнопка / элемент списка / пункт меню).
- `find_edit_window(window)` / `set_text(control, text)` — поле ввода, ввод.
- `select_item(control, text)` — выбор из списка/комбобокса.
- `open_menu(window, item, subitem=None)` — проход по меню.
Все синхронные, вызываются из фонового потока через `asyncio.to_thread`.

### 2.2 `ui_agent.py` — цикл взаимодействия (новый)
Вход: `goal` (короткая цель от планировщика). Выход: `(status, description)`.
Цикл:
1. **Снимок**: UIA-дерево активного окна (`get_window_elements`).
2. **Решение по данным**: строгими UIA-запросами сопоставить текст цели с
   элементами (найти чат по имени → клик); иначе — следующее действие.
3. **UIA-фолбэк**: если UIA не дал кандидата (canvas-UI, нестандартная
   отрисовка) — скриншот + VLM в режиме координат: модели даётся вопрос
   «где на экране кнопка/элемент X?», она отвечает координатами
   (bbox); если модель не отдаёт строгие координаты — описательный ответ
   и точечный визуальный поиск (ограниченная область + повтор). Точный
   механизм координат уточняется на этапе 2. Далее `mouse_click(x, y)`.
4. **Действие**: выполнить (клик/ввод/выбор), строки прогресса в UI-чат.
5. **Проверка**: пауза (~0.8–1.2 c), свежий снимок; состояние окна
   изменилось к цели? Да → следующий шаг к цели; нет → повторный анализ.
Окончание: цель достигнута (статус по проверке) или «застрял» (лимиты ниже).

Окно фиксируется в начале задачи и не меняется (кроме явного плана).

### 2.3 `actions.py` — новые примитивы
- `ui_do_task` — точка входа в `ui_agent` (params: `goal`).
- Обёртки тонких кликов для прямых планов: `ui_click_by_text`,
  `ui_set_text`, `ui_select_item`.

### 2.4 `local_brain.py` — планировщик высокого уровня
`_system_prompt` получает примеры интерфейсных команд. Для
«напиши Диме в телеграм…» план возвращает:
```
{"kind": "actions", "steps": [
  {"action": "open_app", "params": {"app": "telegram"}, ...},
  {"action": "ui_do_task", "params": {"goal": "отправить сообщение «встретимся в 12» Диме"}}
]}
```
Координаты и кнопки планировщик НЕ выдаёт — их находит низкий уровень.

### 2.5 `ws_client.py` — интеграция
Шаг `ui_do_task` исполняется через `_execute_local_steps` как обычный
шаг (обёртка в `actions.py`). Количество шагов плана лимитируется как
сейчас; сам UI-цикл держит свои лимиты (см. §4).

## 3. Поток (кейс-успех)

```
«напиши Диме в телеграм: встретимся в 12»
  → build_plan → [open_app(Telegram), ui_do_task(goal)]
  → open_app : окно Telegram активно, фиксируем окно
  → ui_do_task(goal):
       UIA-дерево → элемент списка «Дмитрий» → клик
       → снимок: диалог открылся? (поле ввода присутствует)
       → find_edit_window → set_text «встретимся в 12»
       → Отправить: кнопка «Отправить» (UIA) или Enter
       → снимок: плашка сообщения появилась → done
  → в чат: «Готово, отправила «встретимся в 12» в чат с Дмитрием».
```

## 4. Безопасность, лимиты, ошибки

- **Confirm** (как сейчас, `classify_steps`): только разрушительные —
  удаление/перезапись файлов. Отправка сообщений подтверждений НЕ требует.
- **Стоп-лист**: цикл НЕ вводит пароли, PIN, номера карт, CVV, промокоды.
  Если цель или найденное поле распознаётся как секретное — стоп и вопрос
  человеку, без самостоятельного ввода.
- **Итерации**: максимум 12 шагов UI-цикла на задачу.
- **Стоп-правило**: повторный клик по одному и тому же элементу/координатам
  без изменения состояния окна → «застрял, вот что вижу».
- **Таймаут задачи**: ~90 секунд → честное «не получилось» + что видно.
- Прогресс UI-цикла пишется в UI-чат короткими строками («вижу чат
  «Дмитрий», кликаю…»), чтобы было видно, что Ева делает.

## 5. Тестирование

| Слой | Что | Как |
|---|---|---|
| Юнит `ui_automation` | клик/ввод/поиск по тексту/роли | мок-дерево (синтетический UIA-граф из dict), без живых окон |
| Юнит `ui_agent` | лимиты итераций, стоп-правила, смена окна, VLM-фолбэк | фейковый «UI-контекст» (имитация состояния окна) + mock `describe_screen` |
| Юнит `actions`/`ws_client` | интеграция шага в план, статусы | мок-адаптеры |
| Живой | Notepad (ввод+меню), Telegram Desktop (кейс целиком) | pytest со скипом, если приложение не запущено; финальный прогон с владельцем |

## 6. Этапы

1. **UIA-адаптер** (`ui_automation.py`) + юниты на моках + живой Notepad.
   Зависимость: `pip install uiautomation` в `eva_agent`.
2. **UI-цикл** (`ui_agent.py`, шаг `ui_do_task`) + лимиты/стоп + VLM-фолбэк
   (bbox) → юниты на фейковом окне.
3. **Планировщик**: примеры `ui_do_task` в `_system_prompt` + связка в
   `ws_client` (лог в чат).
4. **Живой кейс**: Telegram Desktop end-to-end с владельцем; попутно —
   фикс бейджа чата (см. память `chat-badge-open-tab-bug`).

## 7. Открытые вопросы / вне скоупа

- Поддержка web-интерфейсов (DOM/DevTools) — отдельная работа, вне скоупа
  этого релиза (мишень — нативные приложения + VLM-фолбэк).
- Мультимедиа/печать/сеть — следующие итерации расширения «всё как человек».
- UIA работает не для всех приложений (например, некоторые Electron-UI и
  игры не отдают дерево) — в этом случае только VLM-фолбэк (медленнее).
