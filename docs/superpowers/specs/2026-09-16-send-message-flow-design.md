# Спек: Поток «отправить сообщение» — уточнение, открытие приложения, поиск контакта

Дата: 2026-09-16
Статус: дизайн согласован с владельцем (брейншторм ✅), ожидает ревью спека.

## 1. Проблема

Сегодня «напиши Диме в телеграм: встретимся в 12» работает, но только если:
- мозг положил в план `open_app(telegram)` + `ui_do_task` (пример в промпте уже есть);
- **композер уже открыт** — `run_ui_task` только вводит текст и жмёт Enter, но не открывает
  приложение и не ищет контакт.

Чего нет вообще:
- **уточнение «куда писать?»**, если адресат не назван («напиши привет» — мозг планирует
  `ui_do_task` в активном окне, может уехать не туда);
- **открытие целевого приложения/сайта** изнутри `run_ui_task`;
- **поиск контакта/чата по имени** в открытом приложении.

Требование владельца (2026-09-16): когда пользователь просит написать сообщение, Ева
1) спрашивает, куда писать, если адресат не назван;
2) открывает нужную программу или сайт;
3) ищет контакт или чат;
4) отправляет сообщение.

Решение владельца по развилкам:
- **диалог** — память намерения (двухходовка), не только «повтори команду»;
- **охват** — любое приложение/сайт (универсальная схема), не только Telegram;
- **подтверждение** — никогда (fire-and-forget, как и текущая отправка без конфирма);
  единственный guard вместо подтверждения — проверка композера перед отправкой
  (не нашёл чат → ничего не отправляется, честный `stuck`).

## 2. Архитектурный выбор

Подход **A — «умный `run_ui_task` + память намерения в агенте»**:

- вся новая логика живёт на desktop-агенте (`eva_agent/`); сервер-бот (`brain bot/`) почти
  не меняется — вопрос «куда?» и ответ на него идут обычными `chat`/`chat_result`
  сообщениями, которые сервер уже умеет ретранслировать;
- мозг (local_brain, qwen2.5vl) остаётся бес-состояния — двухходовка реализуется одним
  полем «незакрытой заготовки» на агенте и пере-планированием на каждый ход;
- строгий UIA первичен, VLM-скрин — это **наблюдатель** (описание при `stuck`), а не
  исполнитель клика (координатного канала «VLM → клик» у нас нет и в рамках фичи не
  лепим).

## 3. Поток данных (двухходовка)

```
«напиши привет»                        (Telegram / чат приложения / голос → relay_to_agent)
  └─ агент: pending пусто → build_plan
       └─ мозг: просьба писать, адресат не назван
            → kind=need_destination, pending {prefix:"напиши", text:"привет"}
       └─ агент: сохранить pending; ответ «Куда написать? Например: в телеграм Диме»
«в телеграм Диме»
  └─ агент: pending есть, сообщение НЕ начинается с глагола-действия → это ОТВЕТ
       → склейка «напиши в телеграм Диме: привет», чистим pending, build_plan(склейка)
       → план: actions [open_app("telegram"), ui_do_task("напиши Диме в телеграм: привет")]
       └─ исполнение: открыть → найти чат «Дима» → ввести «привет» → Enter → «Сделала: …»
«отмена» / «не надо»                    → чистим pending → «Отменила.»
«напиши в вк Ане: привет» (сразу всё)   → без вопроса, одним проходом (pending не трогаем, он пуст)
```

Правила решения «ответ vs новая команда», когда pending непустой:
- сообщение начинается с глагола-действия из фиксированного списка
  `напиш|отправ|сообщи|введи|открой|запусти|найди|сделай` — **перезапись**:
  чистим заготовку, планируем как есть;
- иначе — **ответ адресата**: склейка `f"{pending.prefix} {answer}: {pending.text}"`.
- `отмена|отмени|не надо|не надо писать|cancel` — чистка + «Отменила.».

## 4. Компоненты

### 4.1 local_brain (`eva_agent/local_brain.py`)
- Новый kind `need_destination`:
  `{"kind": "need_destination", "text": "...", "pending": {"prefix": "...", "text": "..."}}`.
- Промпт: правило «просят написать/отправить, адресат не назван (нет „в <куда>") →
  `need_destination` с текстом сообщения». Примеры в `_system_prompt` дополнить
  (двухшаговый пример уже есть на «напиши Диме в телеграм»; добавить «напиши привет» →
  need_destination).
- Детерминированный страховочный детектор (фолбэк на причуды qwen2.5vl): если цель
  содержит «напиш|отправ|сообщ|смс», но НЕ содержит адресат-маркер из `_APP_HINTS`
  (см. 4.3) — мозг всё равно отдает `need_destination`. Он не заменяет промпт, а ловит
  случай, когда модель ошиблась.
- `parse_plan`: принять `need_destination` в whitelist kind-ов.

### 4.2 Память намерения (новый модуль `eva_agent/pending_intent.py`)
- `PendingIntent`-тип `{prefix: str, text: str}`;
- `store/get/clear` — одна заготовка в памяти процесса (модульные функции с замыканием на
  глобальную переменную), перезапуск агента её теряет — это ок (пользователь повторит).
- Функция решения `interpret_response(pending, msg) -> "answer" | "replace" | "cancel"` +
  `merge(pending, answer) -> goal_str`.
- Подключение: в обработчике `chat`-сообщения `ws_client.py` ДО `build_plan` — по схеме
  из §3.

### 4.3 `run_ui_task` (`eva_agent/ui_agent.py`)
Расширить send-поток до полноценного «открыть → найти контакт → написать → отправить».

**Парсер цели** `_parse_send_goal(goal) -> (dest, contact, payload)`:
- `dest`: адресат-приложение или сайт. Расширить `_APP_HINTS`:
  - `телеграм/telegram` → `open_app("telegram")`;
  - `вотсап/whatsapp/ватсап` → `open_app("whatsapp")` или фолбэк `open_website("web.whatsapp.com")`;
  - `вк/вконтакте` → `open_website("vk.com")`;
  - `дискорд/discord` → `open_app("discord")` или `open_website("discord.com")`;
  - `браузер` → активное окно браузера.
  Карта адресатов `_DEST_MAP`: goal-ключевые слова → способ открытия (app-имя или url).
- `contact`: имя контакта — заглавные слова из goal минус стоп-слова, минус адресат-слова,
  минус payload. (Способом `_click_targets`, но отфильтрованный.)
- `payload`: `_extract_payload` (существующий, кавычки или после «:»).

**Исполнение send-цели** (новая последовательность в цикле, до ввода текста):
1. Окно цели: если `_has_window_hint` и подходящего окна в `list_windows()` нет — открыть
   через `actions.open_app`/`actions.open_website` (по `_DEST_MAP`), подождать ~1.5 c,
   перечитать `list_windows()` и выбрать окно (прежний `_pick_ui_window`).
2. Клик по контакту строгим UIA: `ui.click_by_text(win, contact)` — в приложениях, где
   контакты есть в дереве UIA, этого хватает.
3. Не вышло → встроенный поиск приложения: новый `ui.find_search_edit(win)` → `set_text`
   → `send_enter`. (Telegram открывает первый результат чатом.)
4. Стоп-проверка перед отправкой: `win` → `ui.find_message_input(win)` непустой.
   - Да → существующий ввод payload + Enter → `done`.
   - Нет → честный `stuck` с текстом «не нашла чат <contact>…» и последним взглядом.

Обычный (не send) ввод и клики не меняются. `did_action`/статусы — без ложных `done`.

### 4.4 `ui_automation.py`
- `find_search_edit(window)` — инверсия `find_message_input`: верхний edit, чьё имя похоже
  на поиск (`_SEARCH_LIKE`) или самый верхний по y. Возвращает dict-элемент или None.
- Переиспользуем `set_text`, `send_enter`, `click_by_text`.

### 4.5 Сервер (`brain bot/`)
Почти без изменений. `need_destination` приходит как `chat_result` с текстом вопроса —
`_deliver_text` уже всё умеет. Никаких новых хендлеров подтверждений.

## 5. Ошибки и безопасность

- «отмена» на вопрос → чистка pending → «Отменила.».
- Ответ без адресата после вопроса («я не знаю» / «всё равно») → повторный вопрос.
- Ошибка открытия — статусы `open_app`/`open_website` (уже честные).
- Контакт не нашёлся → `stuck`, ничего не отправлено (стоп-проверка композера).
- Секреты: stop-list `_looks_secret` применяется и к тексту-заготовке (payload), вызов
  фичи с секретом → `error` как сегодня.
- Подтверждения разрушительных действий не затрагиваются.
- Pending не переживает рестарт агента — это ожидаемо и безопасно.

## 6. Тесты (TDD)

- `local_brain`: `parse_plan` принимает `need_destination`; детектор без-адресата отдаёт
  pending; промпт-примеры содержат новый кейс.
- `pending_intent`: store/get/clear; `в телеграм Диме` → «напиши в телеграм Диме: привет»;
  новая команда с глаголом → замена; `отмена` → clear + ответ.
- `ui_agent`:
  - парсер goal → (dest, contact, payload) для «напиши в вк Ане: привет» и
    «напиши Диме в телеграм: встретимся в 12»;
  - окно не открыто → вызывается `open_app`/`open_website` и работа идёт в новом окне;
  - клик по контакту → `done`;
  - поиск→Enter→композер→payload→Enter → `done`;
  - нет композера после поиска → `stuck`, никакого set_text/Enter в отправку;
  - VLM-взгляд по-прежнему не даёт ложного `done`.
- `ui_automation`: `find_search_edit` берёт верхнее/поисковое поле; не пересекается с
  `find_message_input` (один — верх/поиск, другой — низ/композер).
- Живой E2E: Ева сама открывает Telegram, ищет «Дима», открывает чат, отправляет
  «встретимся в 12»; проверка глазами (Ruling 6), что плашка легла в правильный чат
  (переиспользуем `run_e2e_send.py`-логику).
